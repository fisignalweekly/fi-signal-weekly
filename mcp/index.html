MCP server for partners

Connect your AI assistant or integration to FI Signal Weekly. The MCP server gives read-only access to the same published data as the site: the signal board (mergers and acquisitions, executive moves, core conversions, charter and digital banking changes), the institution directory, call-report assets and the tech stack evidence on each institution page. Every signal links to its public source.

Endpoint

https://fi-signal-mcp.fisignal.workers.dev/mcp
  • Transport: MCP Streamable HTTP (stateless, JSON responses). No session handling needed.
  • Auth: Authorization: Bearer <your API key> on every request.
  • Read-only. All tools are safe to call repeatedly.
  • Errors: 401 missing, invalid or revoked key; 429 rate limit (60 requests a minute per key; retry after 60 seconds).

Get an API key

Keys are issued per partner during the preview. Email hello@fisignalweekly.com with the subject “MCP API key” and a line on how you plan to use the data.

Your key starts with fisw_. Treat it like a password: keep it in a secret store and never commit it or paste it into shared documents. If a key leaks, email us and we’ll revoke it and send a new one.

Connect as a remote MCP server

Clients that support remote MCP servers take a URL and headers:

{
  "mcpServers": {
    "fi-signal-weekly": {
      "url": "https://fi-signal-mcp.fisignal.workers.dev/mcp",
      "headers": { "Authorization": "Bearer ${FISW_API_KEY}" }
    }
  }
}

A client that only runs local (stdio) servers can bridge with mcp-remote:

{
  "mcpServers": {
    "fi-signal-weekly": {
      "command": "npx",
      "args": ["-y", "mcp-remote",
               "https://fi-signal-mcp.fisignal.workers.dev/mcp",
               "--header", "Authorization:Bearer ${FISW_API_KEY}"],
      "env": { "FISW_API_KEY": "fisw_..." }
    }
  }
}

From code, with the official MCP TypeScript SDK:

import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";

const client = new Client({ name: "my-app", version: "1.0.0" });
await client.connect(new StreamableHTTPClientTransport(
  new URL("https://fi-signal-mcp.fisignal.workers.dev/mcp"),
  { requestInit: { headers: { Authorization: `Bearer ${process.env.FISW_API_KEY}` } } }));

const res = await client.callTool({
  name: "search_signals",
  arguments: { types: ["m_and_a"], limit: 5 } });
console.log(JSON.parse(res.content[0].text));

Or raw JSON-RPC with curl:

curl -s https://fi-signal-mcp.fisignal.workers.dev/mcp \
  -H "Authorization: Bearer $FISW_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"search_signals",
                 "arguments":{"types":["executive"],"states":["PA"],"limit":3}}}'

Each tool returns one text content block containing JSON.

Tools

search_signals

Search published signals, newest event first (or "sort": "added_desc" for newest published). Paginate with next_cursor.

ArgumentTypeNotes
querystringAll words must appear in the institution name, summary or type label
typesstring[]Types or groups, e.g. ["m_and_a","executive"]
statesstring[]Two-letter codes
min_assets_usd, max_assets_usdnumberInstitution total assets in USD
event_date_from, event_date_toYYYY-MM-DDWhen the event happened
added_from, added_toYYYY-MM-DDWhen it was published on the board
fi_idstringOne institution (fdic-<CERT> or ncua-<charter>)
limit1–100Default 25
cursorstringnext_cursor from the previous page

Example: M&A at institutions over $500M in three states.

{"name": "search_signals",
 "arguments": {"types": ["m_and_a"], "states": ["PA","OH","MI"],
               "min_assets_usd": 500000000, "limit": 5}}

Returns { total, count, next_cursor, signals }. Each signal:

{ "id": "t199", "type": "merger", "type_label": "Pending merger",
  "type_group": "m_and_a", "institution": "…", "state": "MI",
  "event_date": "2026-11-04", "added": "2026-11-13",
  "summary": "…", "source_url": "https://…",
  "fi_id": "fdic-…", "fi_name": "…", "charter_type": "bank",
  "assets_usd": 1234567000, "assets_basis": "call_report",
  "assets_as_of": "2026Q2",
  "fi_page_url": "https://fisignalweekly.com/fi/mi/…/",
  "board_url": "https://fisignalweekly.com/#t199" }

assets_basis is call_report (FDIC or NCUA) or reported_approx (the approximate figure in the announcement).

get_fi_profile

One bank or credit union. Look up by fi_id, by slug (the path or full URL of its page under https://fisignalweekly.com/fi/) or by name with an optional state. An ambiguous name returns { "ambiguous": true, "candidates": [...] }.

{"name": "get_fi_profile", "arguments": {"fi_id": "fdic-14969"}}

Returns directory details (name, charter, city, state, website, holding company, page URL), financials (latest total assets, deposits and loans, a nine-quarter asset trend, 1- and 2-year asset growth, members or offices, and regulator history such as mergers and name changes), peer_benchmarks (industry median and aggregate asset growth for all banks or all credit unions), tech_stack (as in get_tech_stack) and the institution’s published signals.

list_new_signals_since

For syncing into a CRM or another system. Returns signals published on or after since, oldest first, in a stable order.

ArgumentTypeNotes
sinceYYYY-MM-DDPublish date, inclusive
typesstring[]Optional
limit1–200Default 100
cursorstringnext_cursor from the previous call
 
{"name": "list_new_signals_since",
 "arguments": {"since": "2026-11-01", "limit": 100}}

Returns { since, count, has_more, next_cursor, data_updated, signals }. Keep calling with next_cursor while has_more is true. Save the last next_cursor and pass it with the same since on your next sync to get only newer rows. Dedupe on id. Polling once or twice a day is plenty.

get_tech_stack

Technology providers for up to 100 institutions per call.

{"name": "get_tech_stack",
 "arguments": {"fi_ids": ["fdic-30788", "ncua-62918"]}}

Each institution has four fields: digital (retail digital banking), digital_business, core and billpay. Each field returns value, status (current or announced), evidence_type (Login page scan, Vendor press release, FI announcement, Press release or Regulator filing), source_url, last_updated and note, plus replaces when an announced change replaces the current vendor and evidence with every row behind the field.

identified: false means there is no public evidence yet. Core and bill pay come only from public announcements and are never inferred from the digital banking vendor.

Notes

  • Only data published on fisignalweekly.com, refreshed as the site updates. data_updated in responses shows the data date.
  • Every signal links its public source. This is a research aid, not advice; verify before acting.
